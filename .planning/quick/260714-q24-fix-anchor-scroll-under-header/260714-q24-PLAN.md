# Quick task q24 — Anchored headings scroll under the sticky header

**Date:** 2026-07-14
**Spec:** SITE-12 (visual polish) — docs-site UX defect, no content change
**exit-impact:** ops

## Problem

Clicking a heading anchor (or a TOC / in-page `#fragment` link) on
docs.ocutrap.com scrolls the target heading to the very top of the viewport,
where the 56px sticky `.site-header` covers it. The heading text ends up
hidden and the page appears to have over-scrolled (reported on
`/troubleshooting/...` "After Release", applies to every heading site-wide).

Root cause: `docs-site/app/globals.css` sets `html { scroll-behavior: smooth }`
but no scroll offset, so the browser aligns anchor targets with viewport top,
ignoring the sticky header.

## Plan

1. Add `scroll-padding-top: 80px` to the `html` rule — 56px header + 24px
   breathing room, matching the 80px top offset the TOC highlight observer
   already assumes (`components/toc.tsx` `rootMargin: "-80px …"`). This covers
   heading self-links, TOC links, in-page cross-links, and hash-on-load.
2. `npm run build` in `docs-site/` + browser-verify an anchor click.
3. PR to main (merge auto-deploys via Vercel, SITE-05). No markdown touched,
   so no KB-PDF regen.
